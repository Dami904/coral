The problem

The same questions flood crypto communities, and re-checking them costs real money.

"Is this token worth looking at?" gets asked hundreds of times about the same handful of contracts. Paying for a fresh check on every single ask is wasteful. Never checking at all is unsafe. Forgetting a verdict you already paid for is worse than either.

Coral caches what it learns, so it only pays once per contract per staleness window. That dependency is provable, not decorative: delete its memory, and it starts paying again for answers it used to give away for free.

How it works

Four steps, in a fixed order the agent can't skip.

01

Receive

A message arrives over Ping, Sibyl Labs' on-chain agent-to-agent protocol on Base.

02

Recall

Before anything else: have I already answered this? Checked before payment is even considered.

03

Decide

On a real miss, a deployed contract decides. Four rules, fixed order, no override.

04

Respond

Only now does money move, if it has to. The verdict is cached; the decision is journaled.

Partner stacks

Base-ecosystem integrations, each doing real work.

Ping

Sibyl's on-chain agent-to-agent messaging protocol. Inbound message, decision core, reply, through a poll loop tracking its own cursor.

SpendGuard

A Solidity contract the agent's own wallet can only request payment from, never command. Four rules, a human-approval tier, a timelock on policy changes.

Sibyl Memory

The mandatory gate this whole build is judged on: a local, queryable cache reached over the standard MCP interface.

Gateway mode

The mirror case: other agents pay Coral, over Ping, for the same lookup. Payment is verified from the mined receipt, never trusted on claim, and redeemable exactly once.
